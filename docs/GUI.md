# 데스크톱 앱 사용 설명서

`lz` 데스크톱 앱의 모든 버튼과 화면 요소가 무엇을 하는지 설명합니다.
점수를 **해석**하는 방법은 [점수 읽는 법](#점수-읽는-법) 절에 있습니다.

실행:

```
dist\lz.exe          Python 없이 실행
run-gui.bat          소스에서 실행
python -m lz gui     명령줄에서 실행
```

---

## 화면 구성

창은 위에서 아래로 네 단계이고, **순서대로 쓰도록** 되어 있습니다.
표적을 먼저 정하지 않으면 분석 버튼이 동작하지 않습니다.

```
┌─ 1. target structure ──────────────────────────────┐
│ [Open PDB...] 파일명 chain:[A▾] or sequence:[ ] [Use]  [도움말] │
├─ 2. measured geometry ─────────────────────────────┤
│ 사슬 목록, 측정된 레지스터, 평행/역평행, 경고       │
├─ 3. find partners ─────────────────────────────────┤
│ [Screen known zippers] [Design partners]            │
│ pairs:[2] [Design orthogonal set]                   │
│ [Save CSV...] [Save AlphaFold FASTA...]             │
├─ 4. ranked candidates ─────────────────────────────┤
│ 점수 표 (열 제목 클릭 → 정렬)                        │
└────────────────────────────────────────────────────┘
 상태 메시지                              [진행률 바]
```

---

## 1. target structure — 표적 정하기

### `Open PDB...`

PDB 파일을 엽니다. 구조를 넣으면 헵타드 레지스터를 **예측하지 않고
좌표에서 측정**하므로, 가능하면 이 방법을 쓰세요. 서열만 쓸 때 가장
불확실한 단계가 사라집니다.

시험용 구조가 없으면:

```
python tools/fetch_structure.py 2ZTA
```

### `chain:` 드롭다운

파일에 나선이 여러 개면 어느 사슬을 **표적**으로 삼을지 고릅니다.
바꾸면 즉시 다시 분석합니다. 나머지 사슬 중 가장 가까운 것이 자동으로
파트너로 선택되고, 레지스터는 그 둘의 기하로 측정됩니다.

### `or sequence:` + `Use`

구조 없이 아미노산 서열만 입력합니다. 이 경우 레지스터는 **측정이 아니라
예측**이며, 2단계 패널에 그 사실이 표시됩니다. 구조가 없을 때만 쓰세요.

### `도움말 (F1)`

이 문서를 포함한 모든 설명서를 앱 안에서 엽니다. **F1 키로도 열립니다.**

왼쪽 목록에서 문서를 고르고, 본문의 링크를 클릭하면 해당 문서로 이동합니다.
`Esc`로 닫습니다. 작업하면서 옆에 띄워두도록 창을 하나만 재사용합니다.

문서는 **exe 안에 함께 들어 있습니다.** 실행파일만 받은 사람도 읽을 수 있고,
인터넷 연결이나 Markdown 뷰어가 필요 없습니다.

## 2. measured geometry — 읽기 전용 결과

버튼이 없는 정보 패널입니다. 여기 내용을 확인하지 않고 3단계로
넘어가면 안 됩니다.

표시되는 것:

| 항목 | 의미 |
|---|---|
| 사슬 목록 | 찾은 나선과 잔기 범위 |
| `orientation` | 평행 / **역평행** |
| `heptad offset` | 첫 잔기가 어느 헵타드 위치에 오는지 |
| `register fit` | 이상적 coiled coil 프로파일과의 상관계수 (1에 가까울수록 좋음) |
| 코어 잔기 코사인 | 각 잔기가 상대 나선을 얼마나 똑바로 향하는지 (1.0 = 정면) |
| 비폴리머 그룹 | 파일에 들어 있는 리간드·캡 (예: ACE) |

### 빨간 글씨로 뜨는 경고

- **ANTIPARALLEL** — 점수 모델은 평행 이중나선만 가정합니다. 역평행
  구조에서는 **3·4단계 결과가 의미 없습니다.**
- **register fit이 낮음** — 이 계면이 정규 coiled coil처럼 보이지 않아
  헵타드 할당을 믿을 수 없다는 뜻입니다.
- **사슬이 하나뿐** — 상대가 없어 레지스터를 측정할 수 없으므로 서열
  예측으로 자동 전환됩니다.

## 3. find partners — 분석 버튼 세 개

세 버튼은 **같은 표를 채우지만 서로 다른 질문에 답합니다.**
그래서 결과에 따라 표의 열 제목과 설명이 바뀝니다.

### `Screen known zippers`

문헌에 발표된 지퍼 라이브러리(`data/zippers.json`)를 표적과 짝지어
순위를 매깁니다. 즉시 끝나며 새로 만드는 것은 없습니다.

각 후보를 **두 번** 채점합니다 — 표적과의 이종이량체, 그리고 자기
자신과의 호모다이머. 순위는 결합력이 아니라 **둘의 차이**로 매깁니다.
잘 붙지만 자기들끼리 더 잘 뭉치는 후보는 용액에서 표적을 만나지
못하기 때문입니다.

> **결과는 실존하는 분자입니다.** 다만 서열 문자열 자체는 원 논문과
> 대조되지 않았습니다. 각 항목의 `recall` 값이 그 신뢰도를 나타냅니다.
> 합성 전에 반드시 확인하세요. 자세한 내용은 [DECISIONS.md](../DECISIONS.md) 4.1절.

### `Design partners`

이 표적 전용 파트너 나선을 **새로 생성**합니다. 모의 담금질 8회 ×
4000수, 보통 몇 초 걸립니다.

위치별 허용 아미노산을 제한한 상태(*a*는 ILVNAM, *d*는 LMAIV, *e*/*g*는
EKQR …)에서 탐색하므로 나오는 것은 전부 그럴듯한 나선입니다. 목적함수에
음성 설계가 들어 있어 "표적에 잘 붙는다"와 "자기들끼리 안 뭉친다"를
동시에 요구합니다.

> **결과는 세상에 존재한 적 없는 서열입니다.** 아무도 합성하거나 실험한
> 적이 없습니다. 점수가 좋다는 것은 "모델이 잘 붙을 거라 예측한다"는
> 뜻일 뿐입니다.

### `pairs:` + `Design orthogonal set`

`pairs` 개수만큼 **서로 간섭하지 않는 쌍**을 설계합니다 (1~5, 기본 2).
표적을 1번 쌍의 한쪽으로 고정하고 나머지 전부를 동시에 최적화합니다.
3회 × 5000수이며 진행률 바가 움직입니다.

`Design partners`를 여러 번 누르는 것과 **근본적으로 다릅니다.** 따로
설계한 파트너들은 서로를 모르기 때문에 A′가 B에 붙는 것을 막을 장치가
없습니다. 이 버튼은 N×N 상호작용 행렬 전체를 한꺼번에 최적화합니다 —
3쌍이면 6개 나선에 15가지 상호작용이 가능한데 원하는 것은 3개뿐이고
나머지 12개가 전부 경쟁자입니다.

**단백질 연결 시스템을 실제로 구축할 때 쓰는 버튼입니다.** 보통 여러 쌍이
한 세포 안에서 동시에 작동해야 하기 때문입니다.

쌍 개수가 늘수록 난이도가 급격히 올라갑니다: 2쌍은 쉽고, 3쌍은 무난하고,
4쌍 이상은 실패할 수 있습니다.

### `Save CSV...`

현재 표를 CSV로 내보냅니다. 결과가 있어야 활성화됩니다.

첫 줄에 **어느 질문에 답한 결과인지 주석으로 기록**되고, 열 제목도 그에
맞게 달립니다. 몇 달 뒤 파일만 봐도 숫자의 의미를 알 수 있게 하려는
것입니다.

### `Save AlphaFold FASTA...`

ColabFold / AlphaFold-Multimer 입력 파일을 씁니다.

**이종이량체뿐 아니라 호모다이머도 함께** 내보냅니다. 원하는 복합체만
예측해서는 특이성을 알 수 없고, 특이성이 전부이기 때문입니다. 저장 후
결과 판독 기준이 안내 창으로 뜹니다.

## 4. ranked candidates — 결과 표

- **열 제목 클릭** → 그 열로 정렬, 다시 클릭하면 역순
- **초록색 행** → 표적(또는 의도한 짝)을 경쟁자보다 선호하는 후보
- **붉은색 행** → 경쟁자에게 지는 후보

표 아래 회색 설명문은 **현재 모드에 맞춰 바뀝니다.** 숫자를 해석하기
전에 읽으세요.

## 점수 읽는 법

열 제목이 버튼에 따라 달라집니다. 같은 자리의 숫자가 **다른 것을
비교한 결과**이기 때문입니다.

### Screen / Design 결과 (2체 비교)

| 열 | 의미 |
|---|---|
| `binds target` | 이 후보를 **표적과** 짝지은 점수 |
| `self-pairs` | 같은 후보를 **자기 자신과** 짝지은 점수 |
| `specificity` | `binds target` − `self-pairs` |

음수가 안정적이라는 뜻입니다. 핵심은 **specificity** — 음수면 후보가
자기 호모다이머보다 표적을 선호합니다.

### Orthogonal set 결과 (집합 전체 비교)

| 열 | 의미 |
|---|---|
| `cognate pair` | 이 사슬과 **의도한 파트너**의 점수 |
| `self-pairs` | 이 사슬과 자기 자신 |
| `margin vs set` | `cognate pair` − **세트 전체에서 가장 강한 원치 않는 상호작용** |

`margin vs set`의 비교 대상은 자기 호모다이머가 아니라 **세트 안의 최악의
경쟁자**이며, 대개 다른 쌍의 사슬입니다. `verdict` 열이 그 경쟁자가
누구인지 알려줍니다.

음수라고 끝이 아닙니다. 설계 마진(기본 3.0)만큼 이겨야 쓸 수 있습니다 —
그보다 작으면 "앞서긴 하지만 이 모델의 노이즈 범위 안"이라는 뜻입니다.

### 모든 점수에 공통

**보정되지 않았으므로 에너지도 친화도도 아닙니다.** 단위가 kcal/mol처럼
보이지만 순위용 숫자입니다. −12가 −6보다 두 배 세게 붙는다는 뜻이
아니라 "더 유망하다"는 뜻입니다.

점수를 구성하는 세 항(*a*/*d* 코어 패킹, *g*↔*e′* 염다리, 나선 성향)과
그 근거는 [DECISIONS.md](../DECISIONS.md) 1절에 있습니다. 잔기 쌍 단위
분해를 보려면:

```
python -m lz score <서열A> <서열B>
```

## 그 밖의 동작

- **창이 멈추지 않습니다.** 무거운 계산은 작업 스레드에서 돌고 진행률이
  표시됩니다. 계산 중에는 분석 버튼 세 개가 비활성화됩니다.
- **계산 중 창을 닫아도 됩니다.** 안전하게 종료됩니다.
- **오류는 대화상자로 뜹니다.** 앱이 죽지 않고 버튼이 다시 활성화됩니다.

## 다음 단계

이 프로그램은 서열 수준에서 후보를 좁히는 도구입니다. 여기서 나온
결과는 **예측이지 검증이 아닙니다.**

1. `Save AlphaFold FASTA...` → ColabFold / AlphaFold-Multimer로 구조 확인
   (ipTM은 신뢰도이지 친화도가 아니라는 점에 주의)
2. 실험 검증 — CD 융해로 나선성과 Tm, SEC-MALS나 AUC로 올리고머 상태,
   ITC/SPR이나 pulldown으로 실제 친화도

실험 Tm 데이터가 모이면 `python -m lz calibrate`로 점수 모델을 보정할
수 있습니다. 현재 이 프로젝트에서 가장 큰 개선 여지입니다.
